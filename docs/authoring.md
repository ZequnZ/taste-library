# Authoring collection entries

`collection.json` is the entry and category registry. `entries` contains user-approved collection material. `demonstrations` contains the requested review examples and conveys no confirmed taste.

## Save an entry

1. Provide the source, selected detail, original context, proposed categories, related family, and the user's reaction.
2. Present any inferred preference as a candidate and ask for save confirmation.
3. After confirmation, add the documented entry and permitted media/source. Register its stable ID, title, description, category, kind (`family` or `element`), example path, and related entry IDs in `collection.json`.
4. Add detail links to `llm.txt`. Record provenance, permissions, applicability, dependencies, and confirmed reaction in an entry document under `entries/`.
5. Run `npm run validate`, `npm test`, and `npm run build`. Exercise the entry's actual interactive behavior where applicable.
6. The user performs commits and pushes.

The current gallery shows primary-category membership. Whole families connect to separately viewable elements through related entry IDs. More advanced category membership and detail media can be developed against actual collection material.

Idea navigation treatments are individual entries, not grouped gallery blocks. Their `study` and `variant` metadata drive `scripts/generate-examples.mjs`, which extracts one treatment from the preserved grouped source. Edit the grouped source or generator, not the generated `examples/letter-*.html` and `examples/line-*.html`. Each detail page and copied source contains one treatment: letter-motion entries remove the shared underline, and underline entries keep the letters still. Gallery cards and the detail Preview load `?variant=<id>`, which shows only the element and follows the site theme; the standalone file keeps its header, caption and Replay. Splitting existing material does not confirm a preferred variant.

## Review examples

Examples under `examples/` are standalone HTML/CSS demonstrations with working interactions. Open them directly or use the gallery's source inspector. Copy source writes the complete HTML to the browser clipboard.

## Publishing

`npm run build` creates `dist/`, including the gallery, `llm.txt`, and standalone example files. `public/llm.txt` and `public/examples/` are generated by validation from root documents and examples. Source permissions and publication authorization must be established before adding third-party material. The GitHub repository is public; local files reach it when the user pushes.
